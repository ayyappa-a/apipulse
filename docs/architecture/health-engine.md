# APIPulse Health Intelligence Engine

## 1. Multi-Signal Provenance

The Health Intelligence Engine correlates three independent signals:
1. `CUSTOMER_OTEL`: Application spans emitted asynchronously via OpenTelemetry OTLP/HTTP.
2. `SYNTHETIC_PROBE`: Independent outbound HTTP probes executed by APIPulse edge runners.
3. `VENDOR_STATUS`: Declared status scraped from public vendor status endpoints.
4. `APIPULSE_ASSESSMENT`: Deterministic mathematical correlation generated by the engine.

## 2. Grey-Failure Theorem

> A vendor API can return HTTP status 200 and publish an "All Systems Operational" status page while suffering from severe tail latency inflation (e.g. 200ms -> 8,450ms).

HTTP 200 is **not** health. The engine evaluates:
- Rolling P95 baseline vs current evaluation window P95.
- Multiplier threshold (default: `>= 3.0×` baseline).
- Absolute latency threshold (default: `>= 1000ms`).
- Hysteresis: requires `RecoveryWindowCount` (default: 3) consecutive healthy evaluation cycles before transitioning from `GREY_FAILURE` or `DEGRADED` back to `HEALTHY`.
